使用场景与适合人群

适合按需求生成鸿蒙应用的开发者

0-1 生成后逐条验收

“生成的应用，需求都做到了吗？”

为每条需求编写单元测试和界面测试，在设备上执行，给出满足、违反或未验证；违反的功能直接修复，测试留在工程里可以重跑。

适合负责 Android 迁移鸿蒙的开发者

迁移后的功能验收

“迁过来的功能还能用吗？”

按需求文档逐条核对迁移结果，可以另给 Android 工程作为行为参照；修复迁移中做错或漏掉的功能。

适合开发者和评审者

改动后回归，交付前核对

“这次改动有没有把已有功能改坏？”

只验证、不改代码，得到一份按需求逐条列出结论和证据的结果，可以直接交给评审。

使用条件
DSH 与插件
DSH ^0.2.1-rc.2，插件 0.1.0-dev.28；Node.js 22.22 或更高。
工程与需求
鸿蒙 Stage 工程根目录：有 build-profile.json5，至少一个模块有 src/main/module.json5；文本格式的需求文档，例如 spec/spec.md。
工具链与设备
DevEco Studio 自带的 SDK、hvigor、ohpm 和 hdc；一台模拟器或测试真机，hdc list targets 能看到。
界面测试用的 Python
Python 3.11 或更高，能导入 hypium 6.1.0.210 和 xdevice；启动 DSH 前把 DT_VERIFY_PYTHON 设为它的绝对路径。
适用范围和限制 ＋
需要需求文档和 Stage 工程

结论按需求文档逐条给出。没有需求文档、不是鸿蒙 Stage 工程时用处不大。

模拟器缺少的能力

相机拍照、振动、端侧 AI 能力、碰一碰在模拟器上测不了，记为未验证；换真机可以补上一部分。验证器在真机上的完整运行还没有验收。

真机上也测不了的情况

Canvas 绘制的内容、没有文字和 id 的控件、通知等系统状态、系统分享目标完成的发送、华为账号登录成功的路径，以及字形、颜色等显示问题。

运行时间与代码改动

一个应用通常要 20–120 分钟，期间独占一台设备。修复会改生产代码，建议在单独的分支上运行，结束后检查改动再合入。

常见问题

安装前需要准备什么？＋

DSH ^0.2.1-rc.2 和 Node.js 22.22+；DevEco Studio 自带的 SDK、hvigor、ohpm 和 hdc；一台模拟器或测试真机；Python 3.11+，能导入 hypium 6.1.0.210 和 xdevice，启动 DSH 前把 DT_VERIFY_PYTHON 设为它的绝对路径。命令行安装还需要 PATH 上能找到 pnpm。

什么样的工程可以用？＋

鸿蒙 Stage 工程：根目录有 build-profile.json5，至少一个模块有 src/main/module.json5。还需要一份文本格式的需求文档，结论按它逐条给出。按需求从零生成的应用和从 Android 迁移来的应用都可以用；迁移的应用可以另给 Android 工程作为行为参照。

一次要跑多久？会改我的代码吗？＋

一个应用通常要 20–120 分钟，期间独占一台设备，同一个应用不要在同一台设备上同时跑两次。允许修复时只改生产代码、不改测试，建议在单独的分支上运行，结束后检查改动再合入。只想验证时，在提问里写明“只验证，不修改生产代码”。

PASS、FAIL、BLOCKED 和 SATISFIED、VIOLATED、UNVERIFIED 有什么区别？＋

前三个是单条用例的执行状态：PASS 结果符合预期，FAIL 结果与预期不符，BLOCKED 缺少环境、设备或前置条件，或证据复核没有通过。后三个是每条需求的结论：SATISFIED 表示有充分证据表明满足，VIOLATED 表示有效证据表明违反，UNVERIFIED 表示证据不足、执行受阻或没有可观察的界面，不会被其他要求的通过补齐。

测试和结果保存在哪里？＋

单元测试在 entry/src/ohosTest/ets/test，界面测试在 entry/src/ohosTest/ui-scripts，可以随代码提交以后再跑。运行目录里，acceptance.json 是验收要求，accepted-plan.json 是审查后冻结的正式计划，attempts/ 下是每次执行的用例状态、截图和控件树，最后一轮运行里的 chain-summary-*.json 是最终汇总。

用模拟器还是真机？＋

都可以。相机拍照、振动、端侧 AI 能力在模拟器上测不了，记为未验证；真机上相机可用但需要人工拍照，振动状态仍需人工确认，碰一碰需要两台真机人工测试。真机要开启开发者模式，工程要配好签名，可以用 DevEco Studio 的自动签名。验证器在真机上的完整运行还没有验收，页面上的效果数据都在模拟器上跑出。

哪些问题测不出来？＋

Canvas 绘制的内容，以及没有文字和 id 的图片、开关定位不到；通知、提醒、后台任务等系统状态读不到；由系统分享目标完成的发送只能确认分享面板被拉起；华为账号登录成功的路径需要真实账号和应用的 AGC 配置；字形显示错误、颜色细节等显示问题看不到，可能判为通过。

安装后出现的子 Agent 角色是做什么的？＋

插件注册 dt-verify Skill 和 5 个名称以“鸿蒙代码验证器子任务”开头的子 Agent 角色，分别用于按功能组编写单元测试、按页面编写界面测试、修复工作项和独立审查测试计划。它们只用于委派，不要用它们新建会话。

页面上的效果数据是怎么得到的？＋

0-1 生成场景：一批按需求生成的应用先做人工验收，有失败或无法验证功能点的 18 个中目前跑完 9 个，3 个修复后通过率提升，修好的功能点都在设备上逐项确认。迁移场景：Cofi 和 AntennaPod 按人工整理的功能清单，对照修复前后的产品代码判定可用性。实验准备、设置和图表见使用文档的“收益”一节。
