ECAT 熵减对抗优化器 v0.1.0-alpha.1

模型自己说「做完了」就行？这个优化器让它改到判别器认为达标为止。

长程任务里，模型经常不按你的要求做，或者改了几处就自我感觉良好。这个插件把生成器和判别器拆成两个独立会话：判别器按你定的判据找问题，把问题清单交给生成器继续改，一轮轮对抗重复直到达标。适用于有明确验收目标的长程任务，比如大规模代码仓跨端迁移。在鸿蒙代码仓迁移场景里，迁移质量从 46.4% 提升到 74.7%。

使用场景与适合人群

适合长程任务的开发者

把验收标准写成维度，判别器逐项检查并给出分数，生成器只按未通过清单继续改。

适合需要跨轮一致性的人

长程任务中途标准走样

“跑到第 20 轮，判据和一开始不一样了？”

判据写在配置和插件里，每一轮都读同一份，不随对话漂移；跨端迁移这类需要逐项对账的任务尤其明显。

适合判据能写清的团队

验收标准能写成检查、但一轮轮改很费人

“编译、接口契约、页面结构这些都能验，就是得反复改十几轮。”

判据明确但打磨轮次长的活：重构、接口对齐、测试修复、跨端迁移。把判据写进去，让它自己循环。

用与不用，过程中的差别
同一件事，左边是只靠一个会话自己改自己判，右边是拆成生成器与判别器两个会话。

      
不使用：一个会话自己改、自己判
判据留在对话里，越往后越模糊；没有可比分数，停在“感觉良好”。
使用：生成器与判别器分开，每轮打分
判别器按固定判据找问题，生成器只改未通过项；每轮都有分数与剩余差异。

      
↳ 判据固定，跨轮次不变
↳ 每轮有可比分数，不再靠感觉
↳ 鸿蒙迁移一个实例：46.4% → 74.7%

    


    

      
装好插件，跑出第一轮
前两步装插件，后三步跑完第一轮迭代。

      

        
使用条件
DSH 版本
0.2.1-rc.2；插件版本 0.1.0-alpha.1。
本机依赖
Python 3.11+（python3 / python / py 启动器任一可用）；uv 可选，装了会快很多。
网络
首次运行需要联网从 PyPI 解析依赖；之后可离线跑循环。
工作范围
只改 ecat.config.yaml 里 paths.target 指向的目录；目录之外不动。

        
插件自带 ECAT 的 wheel 与两个技能，不需要预先安装 ECAT。首次运行会建一个隔离环境并从网络拉取 13 个依赖。

        
适用范围和限制 ＋
不判断业务正确性
熵下降只说明在这组判据上更整齐。判据本身设计错了，循环会高效地朝错误方向优化，所以判据要你自己定、自己复核。
会自动停，但上限由你定
总分连续 stable_iters_to_stop 轮（默认 2）低于 entropy_threshold 时提前结束；否则跑到 max_iterations（默认 100 轮）为止。想中途收手用 /ecat-refine stop，已跑完的产物都保留。
只覆盖你配置的目录
paths.target 之外的改动不会被处理；跨仓库的约束要写成一条显式检查命令，否则循环感知不到。
已有环境不会自动升级
~/.dsh/ecat-venv 存在即复用，不校验版本。插件升级后需手动删掉该目录，再跑一次 /ecat-setup。

      

      
  1. 1
    在 DSH 安装插件 打开「插件」→「实验性插件」旁的「更多」，启用「自定义插件市场」。在「发现」→「添加索引源」填入下方地址，然后安装 ECAT 0.1.0-alpha.1。 插件市场索引
    https://fuxi-ailabs.github.io/dsh-plugin-market/index.json
  2. 2
    确认 Python 可用 插件需要一个 3.11+ 的解释器。装了 uv 的话下面这步会快很多；没有也能跑，会回退到 python -m venv + pip。 Windows 上也可以用 py -3.11 --version 确认。 终端
    python --version
uv --version
  3. 3
    创建托管环境 发送不带参数的 /ecat-setup。它会先建 ~/.dsh/ecat-venv 并安装自带 wheel 与 13 个依赖，装好之后才开始访谈。 环境装不起来时这一步直接失败并报出 uv / pip 的错误，不会进入访谈。 发送给 DSH
    /ecat-setup
  4. 4
    核对环境 再发一次 help，逐项确认依赖可用。注意 help 本身不创建环境，环境没装好时它只会报 NOT ready。 发送给 DSH
    /ecat-setup help
  5. 5
    跑第一轮 在目标工程目录下完成访谈，然后启动循环，再用 status 看熵值和最差维度。 一轮从几分钟到几十分钟不等，循环在后台跑；随时用 /ecat-refine stop 停止。 发送给 DSH
    /ecat-refine start
/ecat-refine status

      
检查结果 ＋
  1. 在 DSH 安装插件
    ECAT 0.1.0-alpha.1 出现在已安装插件中。
  2. 确认 Python 可用
    Python 版本号 ≥ 3.11；uv 有输出版本号，或明确没有安装。
  3. 创建托管环境
    命令回执显示 Created ~/.dsh/ecat-venv（或 Using，表示已有环境）。
  4. 核对环境
    输出 environment: ready，后面逐行列出 13 个包名与版本。
  5. 跑第一轮
    start 返回运行目录；status 给出当前 H、迭代次数和最差维度。

常见问题

      
什么样的任务适合用？＋
验收标准能写成可执行检查、且需要反复改很多轮的任务：大规模重构、接口契约对齐、测试修复、跨端迁移。判据只靠主观感觉的不适合——那种情况循环没有方向。
它和我直接让模型改有什么区别？＋
生成器和判别器是两个独立会话，判别器看不到生成器的解释，只按你定的判据打分。这样不会出现“改了几处就说已完成”，而且每一轮的分数可以互相比较。
一轮要跑多久？跑完我会看到什么？＋
一轮从几分钟到几十分钟，取决于目标规模、维度数量和模型速度，所以循环在后台跑。/ecat-refine status 随时给出最新总分、各维度得分和最近几轮曲线；每轮的改动、分数和日志都留在 .ecat/runs_*/ 下。
46.4% → 74.7% 是怎么来的？＋
这是鸿蒙代码仓迁移场景下的一次运行结果，指标是迁移质量评分。本页只作为该场景的实例引用；具体的维度构成与样本口径以 ECAT 仓库的运行记录为准。
会不会改坏我的代码？＋
它只改 paths.target 指向的目录。发生回归时按 revert_on_regression 自动撤销那一轮；建议在单独分支上跑，结束时检查 diff 再合入。
