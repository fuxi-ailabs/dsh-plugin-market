DSH PLUGIN · v1.0.1

Session Audit

选择一条 DSH 会话，把真实执行轨迹转换为 SIFT 审计输入，查看 finding、证据和 turn 引用，并在右侧面板浏览完整报告。

DSH
0.2.1-rc.2
Node.js
>=24
Bundle
@fuxi-ailabs/dsh-audit-bundle

功能

  • 会话审计工作台：从 Session 轨迹识别 Skill、Workflow 和子 Agent。
  • 三类审计：Skill、Root Workflow 和 Agent 声明审计。
  • 真实报告：复用 SIFT 生成的 HTML 报告和结构化 JSON。
  • 右侧报告面板：展示 summary、finding、证据和 turn 引用。
  • 环境检查：检查 SIFT、Provider Auth 和审计服务。

安装

npm 包@fuxi-ailabs/dsh-audit-bundle
查看 npm 页面 ↗

1. 准备运行环境

  • DSH 0.2.1-rc.2 或同一兼容范围。
  • Node.js 24 或更高版本。
  • sift 命令已安装并在 PATH 中。
  • 需要指令精炼、headline 或 AI critique 时，准备 provider 凭据。

2. 从市场安装

在 DSH 的插件市场中添加索引，找到 Session Audit 并安装。

https://fuxi-ailabs.github.io/dsh-plugin-market/index.json

也可以直接安装当前版本：

dsh plugin --profile <profile> add @fuxi-ailabs/dsh-audit-bundle@1.0.1

安装后重启 DSH。

环境检查

在「插件」→ Session Audit 的配置页检查审计依赖。检查会覆盖 SIFT、Provider Auth 和 siftAudit 服务。

检查项说明
SIFT检查 sift 是否可执行及版本；缺失时显示安装指引。
Provider Auth检查可用的 provider 凭据；审计的确定性部分不依赖 LLM。
Audit Service检查 siftAudit 是否已由 Host 挂载。

使用

从工作台开始

  1. 打开左侧「会话审计」。
  2. 把 Session 拖入工作台，或在 Session 行的「...」菜单中选择「审计会话」。
  3. 选择 Skill、Workflow 或 Agent，确认参数后开始审计。
  4. 审计完成后查看报告与历史记录。

命令行

/sift audit --kind skill --skill <name>
/sift audit --kind root
/sift audit --kind agent --agent <label>

常用选项：

/sift audit <path> --kind skill|root|agent
--sid <sid>
--no-subagents
--no-refine
--no-headline

右侧报告面板

在审计报告卡点击「查看审计详情」，会打开目标 Session 并显示右侧审计报告面板。

当前报告面板是只读展示：

  • 不切换原生 Trajectory View。
  • 不执行 finding 记录聚焦。
  • 不修改 Conversation View。
  • T tag 只显示引用，不支持点击跳转。

使用条件与限制

  • SIFT 是外部运行环境，Bundle 不会自动安装 sift。
  • 审计质量依赖 Session 证据完整性、子会话可读性和 Skill 声明位置。
  • 历史记录保存在 ~/.dsh-insight/dsh-audit/<sid>/。
  • 报告面板当前不做 Trajectory 定位；后续需要 DSH 上游提供公开桥接 API。
