工具与命令

插件注册 11 个只读工具、1 个 tools/pre-execute 守卫和 1 个 /wrsi 命令。工具用原生 JSON Schema 注册，运行时不 import DSH 的包。

只读工具（给 Agent）#

工具参数调用
wrsi_state无GET /api/state
wrsi_sessions无GET /api/sessions
wrsi_sessionidGET /api/sessions/<id>
wrsi_requestsession、seq（≥1）请求视图、记录检查与追踪、该请求的事件
wrsi_assets按空间、类型、状态、目标、会话、PR 等筛选（都可选）GET /api/assets
wrsi_runs无GET /api/runs
wrsi_run_insightssince、until、where[]、group_by、a[]、b[]GET /api/runs/insights
wrsi_loop_statusid（可选）wie loop status <id>；不给时 wie loop list
wrsi_plan_statusplanwie plan status --plan <plan>
wrsi_trialssince、until、method（都可选）GET /api/trials
wrsi_reportsince、untilGET /api/report/rsi

返回结构#

每个工具返回同一种结构：

json
{ "available": true,  "ok": true,  "data": { … } }
{ "available": true,  "ok": false, "error": "404 no such session" }
{ "available": false, "reason": "wrsi-server … is not reachable (…)" }

第一种是成功，data 为 workflow-rsi 的原始返回；第二种是 workflow-rsi 返回了错误；第三种是用不了。结果超过 20000 字符时截断，末尾写明还剩多少字符。

守卫#

tools/pre-execute 守卫拒绝任何名字以 wrsi_ 开头、但不在上表里的工具调用，不论是谁注册的。Agent 因此无法经工具改动 workflow-rsi。

/wrsi 命令（给人）#

类别子命令
读status、sessions、session <id>、assets [key=value …]、loop [<id>]、plan <计划 uri>
写admit <uri> --reason <文字>、publish、loop-resume <id> <rerun|fix|give-up|merge-done>、plan-decide <计划> <需求集/Dnn> <裁决>

写命令缺 --confirm 时只回显将要执行的操作，不执行：

text
/wrsi admit asset://b/rubric/r@1 --reason "复核通过"
Not run. This would admit asset://b/rubric/r@1 with the reason "复核通过" (POST /api/assets/transition).
Repeat the command with --confirm to run it.
