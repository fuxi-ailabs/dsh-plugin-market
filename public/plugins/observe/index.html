DSH BUNDLE · dsh-observe-bundle · v1.2.0

Observe

Observe 是一个观测插件。它负责“导入 + 观测”：一键把当前 DSH 会话送入 Context-Insight，查看 Turn、Tool Call、Skill、Subagent、文件变更和父子执行链路。

主要组成

实际使用中，您只需要一键安装 @fuxi-ailabs/dsh-observe-bundle@1.2.0，即可获得完整的会话观测能力。

组成版本作用
Observe Bundle安装入口1.2.0一次安装完整的观测能力，自带 env-health、Host 和 UX。
dsh-observeHost 插件1.2.0注册 /observe，导出会话、调用 Insight 导入 API，并负责运行时检查与启动。
dsh-observe-uxWeb UX 插件1.2.0在会话页提供“观测”入口、准备状态、错误反馈和 Context-Insight 页面跳转。
dsh-env-health共享运行时1.2.0管理 Context-Insight CLI 的探测、安装和并发安装锁；与 Score 同时安装时复用同一实例。
Context-Insight外部分析运行时0.2.41本地会话分析与观测服务，提供 Turn、Trace、Context、Skill、File 等页面。

能观测什么

01 · TRAJECTORY

Turn 与 Tool Call

按时间查看用户请求、模型决策、工具调用、文件操作、错误和重试过程。

02 · LINEAGE

Subagent 与 Workflow

查看主 Agent 如何拆解任务、派发子代理，以及父子会话之间的执行对应关系。

03 · SKILLS

Skill 与文件上下文

检查 Skill 是否被触发、调用了哪些文件与工具，以及任务要求是否真正进入执行链路。

04 · SESSION

会话统计

查看 Token、Wall Clock、LLM Calls、Tool Calls、Skills 和 Subagents 等会话级指标。

适合哪些场景

  • 长链路任务复盘：定位 Agent 在哪个 Turn 偏离目标、重复试错或漏执行步骤。
  • Subagent 协作检查：确认任务是否被正确拆分、并行执行，以及子代理结果是否回收到主链路。
  • Skill 调试：检查 Skill 是否触发、读取了哪些文件、修改了哪些产物。
  • 问题证据留存：把真实 DSH 会话导入本地 Context-Insight，作为后续审计与评分的基础数据。

使用前后对比

拆分前 / 手动操作

  • 需要同时使用导出、导入、观测和评分等混合能力。
  • 定位会话文件、调用导入接口和打开页面的步骤分散。
  • 观测结果与评分命令耦合在同一个入口里。

使用 Observe 后

  • 点击一次“观测”即可刷新导入并打开会话页面。
  • 运行时准备、服务启动和导入状态在 DSH 内统一展示。
  • 只安装观测能力，不携带评分命令和评分 UX。

边界

Observe 负责导入和观测，不读取评分卡，也不注册 /score。评分能力由独立 Score Bundle 提供；两者都安装时，只共享一次 dsh-env-health 和同一个 Context-Insight 服务。

Context-Insight 是任务执行后的分析工具，不实时介入 Agent 决策。

4. 功能演示

/observe 命令

命令与页面上的“观测”按钮等价，不经过模型，也不占用模型 token。

以下命令在 DSH 的会话输入框中发送，不是在系统终端执行。

/observe
/observe <sid>[,<sid>...]
/observe --no-subagents
/observe --no-open
/observe --status
参数用途
<sid>导入指定会话；不填时使用当前会话。
--out <dir>覆盖本次导出目录。
--no-subagents本次只导入根会话。
--no-open只导入，不打开浏览器。
--base <url>指定 Context-Insight 地址。
--force服务不可用时仍导出会话文件。
--status只检查 Context-Insight 是否可访问。

FAQ

Observe 和 Score 必须一起安装吗？+

不需要。两个 Bundle 完全独立；只安装 Observe 也能导入和观测会话。同时安装时共享 env-health 和 Context-Insight 服务。

以前装过 Insight，安装前要移除旧包吗？+

要。Insight 已拆分为 Observe 和 Score，不再提供 @fuxi-ailabs/dsh-insight-bundle。如果当前 profile 还显示已安装的 Insight Bundle，请先在 DSH「插件」页移除旧包。若同时装有 1.1.x 的 Session Audit、Skill Eval 或 Static Check，请先一并升级到 1.2 Bundle；否则不要先删除共享 Runtime Bundle，因为这些旧插件仍依赖它。确认没有其他旧消费者后，再执行 dsh plugin --profile web remove @fuxi-ailabs/dsh-runtime-bundle，并安装当前 Bundle。

为什么只看到“观测”，没有“打分”？+

当前 profile 只安装了 Observe Bundle。评分入口由 Score Bundle 的 dsh-score-ux 提供。

首次点击较慢是正常的吗？+

首次使用需要下载 Context-Insight 运行时并启动服务，耗时取决于网络和机器；后续会复用本地运行时。

导入失败应该先检查什么？+

依次检查 npm、网络、Context-Insight Runtime 和服务状态，再查看 ~/.dsh-insight/runtime/install.log 与 start.log。

Observe 会把数据上传到云端吗？+

Observe 将 DSH 会话发送给本机 Context-Insight 服务；实际存储位置由 Context-Insight 配置决定。

使用条件与限制

  • 首次准备运行时需要 npm 和网络。
  • Context-Insight 是任务后的观测工具，不实时介入 Agent 执行。
  • 观测结果受会话导出完整度和 Context-Insight 版本影响。
