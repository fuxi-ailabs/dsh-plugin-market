02 BEFORE / AFTER
同一个问题，少一些翻找。
“这份发布说明怎么改成现在这样？”从分散的会话轨迹，到围绕一个文件查看来历。

      
− BEFORE
在对话里找改动
搜索文件名，逐条打开 write / edit，再对照参数与结果。
+ AFTER / AgentLineage
从文件直达证据
选中 release-note.md，把三次写入、来源会话与具体 diff 放在一起看。

      
↳ 同一文件的操作聚合到一起
↳ 每次修改关联来源会话
↳ 沿引用继续核对原始记录

    


    

      
03 WHEN TO USE IT
带着你的问题来。
这些时候，可以让插件帮你找到下一步要看的材料。

      
01 / CODE REVIEW
审查一个可疑改动
“这段配置是谁改的？”
从文件定位修改，再看是哪次会话、哪个工具完成了操作。
02 / TASK REPLAY
接手或复盘历史任务
“昨天那个 Agent 做了什么？”
选择项目的历史任务，查看文件改动及其子会话中的操作。
03 / EVIDENCE CHECK
核对报告里的依据
“这个结论有原文支持吗？”
检查归因报告的引用与证据覆盖，找到需要补充或修订的地方。

DSH 0.2.1-rc.2 · 预览版
完整安装文档 ↗
先做最小实验，再分析真实任务。每一步都有可核对的结果。

        
  1. 01
    准备本地运行环境
    使用 Node 24+、Python 3.12+。先检出与插件匹配的 AgentLineage 发布版本，在仓库根目录安装 Core。
    PowerShell · Windows
    git clone --branch dsh-agentlineage-v0.1.0-alpha.3 --depth 1 https://github.com/fuxi-ailabs/AgentLineage.git
cd AgentLineage
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install ./components/core
$env:AGENTLINEAGE_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
    从设好环境变量的同一终端启动 DSH，让插件能找到这个 Python。其他平台按安装文档配置等效的 Python 路径。
  2. 02
    在 DSH 安装插件
    打开「插件」→「实验性插件」旁的「更多」，启用「自定义插件市场」。在「发现」→「添加索引源」填入下方地址，安装 AgentLineage 0.1.0-alpha.3。
    插件市场索引
    https://fuxi-ailabs.github.io/dsh-plugin-market/index.json
    已有同名旧插件时先卸载旧版，再安装新版。
  3. 03
    确认服务已经就绪
    在项目会话中发送下面这句话。返回能力包含 dsh-native-v4，就可以继续；首次 binding 为 null 是正常的。
    发送给 DSH
    请调用 lineage_status，确认 Core 能力包含 dsh-native-v4。不要显示任何 token。
  4. 04
    做一次最小实验
    让 Agent 用 write 创建一个文件，再用 edit 修改。刷新快照，核对两次确认写入及其证据。
    发送给 DSH
    用 DSH 的 write 工具创建 lineage-check.txt，内容为 hello；再用 edit 把 hello 改成 hello lineage。不要使用 shell 写文件。完成后刷新当前会话的 Lineage 快照，查询这个文件的修改来源，给出调用、成功回执和原文引用。不要让我提供 snapshot_id。
    预期看到：同一文件的两次确认写入，以及各自的调用和回执引用。
  5. 05
    打开视图，继续追溯
    让 Agent 打开当前快照的 Viewer，选择文件并展开 diff。后续又改了文件时，再刷新快照查看新增记录。
    发送给 DSH
    打开当前分析快照的 Viewer。
    Viewer 首次打开需要本机登录；按安装文档在本机读取凭据并粘贴到登录框，不要把凭据发给 Agent。Core 重启后需重新登录。

      

    


    
05 GOOD TO KNOW
使用前，了解这几点。
知道记录覆盖到哪里，才能更准确地理解结果。
快照是一个时间截面＋
继续工作后，发送“刷新当前会话的分析材料”才能查看新增记录。当前 DSH 插件没有持续后台采集。
只解释已观测的记录＋
未导入的会话、缺少成功回执的调用，以及不透明 shell 脚本里的文件操作，可能留下证据缺口。
来源清楚，仍要判断对错＋
溯源与引用检查帮助你核对依据；代码是否正确、业务结论是否成立，需要结合实际结果判断。
