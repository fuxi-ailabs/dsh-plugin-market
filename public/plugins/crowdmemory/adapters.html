接入你的 Agent

先启动本机 Runtime，再选择正在使用的 Agent 安装适配器。适配器负责采集执行事件、交付相关经验，并提供 memory_note、memory_search、memory_read 三个工具。

DSH · OpenClaude · opencode · Codex

1. 启动共用 Runtime

需要 Node.js ≥ 22.18、带 venv 的 Python ≥ 3.10，以及 macOS 或 Linux。以下命令使用独立目录，无需全局安装 Runtime。

终端 A
mkdir -p CMLocal
cd CMLocal
npm install --save-exact @fuxi-ailabs/crowdmemory-runtime@0.1.1
npx --no-install crowdmemory-runtime install --prefix "$PWD/.runtime/crowdmemory"
npx --no-install crowdmemory-runtime start --prefix "$PWD/.runtime/crowdmemory"

保持终端 A 运行。在另一个终端进入同一 CMLocal 目录，设置连接信息，再执行下面所选宿主的安装步骤：

终端 B · CMLocal
export CROWDMEMORY_ENDPOINT_FILE="$PWD/.runtime/crowdmemory/state/endpoint.json"
export CROWDMEMORY_PROJECT="my-repository"

多个 Agent 要复用同一批本机记忆，应连接同一 Runtime，并使用稳定的项目标识；跨项目记录还需要合适的 project/global 范围。Runtime 和宿主应以同一个系统用户运行。Runtime 命令参考

2. 接入 DSH

适用于 DSH 0.1.6-alpha.2 或 0.2.0-rc.2 及以后的 0.2.x。宿主已安装后，在终端 B 执行；web 换成实际使用的 Profile：

终端 B · DSH
dsh plugin --profile web add @fuxi-ailabs/crowdmemory-dsh-adapter@0.1.1
dsh --profile web

在插件列表确认 CrowdMemory 适配器已加载，再检查 Agent 是否提供三个记忆工具。需要固定端点路径、控制推送或启用 workflow 模板时，见DSH 插件配置。从程序坞启动桌面版时，按桌面版配置传入端点。

DSH 适配器使用说明

2. 接入 OpenClaude

适用于 OpenClaude 0.12.0、0.31.0。以下仍在同一 CMLocal 目录执行，下载插件到当前目录后启动宿主：

终端 B · OpenClaude
npm pack @fuxi-ailabs/crowdmemory-openclaude-plugin@0.1.1 --registry=https://registry.npmjs.org
mkdir -p plugin-openclaude
tar -xzf fuxi-ailabs-crowdmemory-openclaude-plugin-0.1.1.tgz -C plugin-openclaude
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 openclaude --plugin-dir "$PWD/plugin-openclaude/package"

初始化后应看到 MCP 服务 plugin:crowdmemory:memory 已连接，并提供三个记忆工具。不加 --bare，该选项会跳过插件。此安装方式面向 OpenClaude；Claude Code 的兼容范围请另行确认。

OpenClaude 插件使用说明

2. 接入 opencode

同一个 npm 0.1.1 适配器支持 opencode 1.x 和 2.x。按正在使用的主版本，将配置合并进项目的 opencode.json；不要覆盖已有配置。

opencode 1.x
{
  "plugin": [["@fuxi-ailabs/crowdmemory-opencode-adapter@0.1.1", {
    "project": "my-repository"
  }]]
}
opencode 2.x
{
  "plugins": [{
    "package": "@fuxi-ailabs/crowdmemory-opencode-adapter@0.1.1",
    "options": { "project": "my-repository" }
  }]
}

从已设置端点变量的终端启动 opencode。1.x 使用 plugin，2.x 使用 plugins；端点也可通过插件选项 endpointFile 指定绝对路径。

opencode 适配器使用说明

2. 接入 Codex

适用于 Codex CLI 0.164.0。以下使用独立的 Codex 配置目录，仍在 CMLocal 中执行：

终端 B · Codex
npm pack @fuxi-ailabs/crowdmemory-codex-plugin@0.1.1 --registry=https://registry.npmjs.org
mkdir -p plugin-codex
tar -xzf fuxi-ailabs-crowdmemory-codex-plugin-0.1.1.tgz -C plugin-codex
export CODEX_HOME="$PWD/.codex-crowdmemory"
codex plugin marketplace add "$PWD/plugin-codex/package" --json
codex plugin add crowdmemory@crowdmemory-codex --json
codex login
codex

按 Codex 提示检查并信任插件 hooks，MCP 工具审批继续由宿主控制。插件应提供三个记忆工具；桌面端和云端的支持范围见插件说明。

Codex 插件使用说明

3. 检查连接与记忆读取

终端 B · CMLocal
npx --no-install crowdmemory-runtime status --prefix "$PWD/.runtime/crowdmemory"

状态应显示 Runtime 运行中。然后在 Agent 中确认三个记忆工具可用；让一个 Agent 写入明确标为测试的记录，再启动另一个 Agent，用 memory_search、memory_read 查找并核对来源。

  • 没有记忆工具：检查宿主是否加载了正确的插件或 Profile。
  • 工具提示记忆暂不可用：检查端点文件是否存在、是否为绝对路径，以及 Runtime 是否仍在运行。
  • 读不到另一条记录：检查是否连接同一 Runtime，以及项目标识和记录的 project/global 范围。

已发布适配器与能力边界

宿主npm 版本接入范围
DSH0.1.1会话、工具结果、压缩、子代理、workflow / goal 事件、推送及三个记忆工具。
OpenClaude0.1.1会话、工具结果、压缩、子代理、推送及三个记忆工具；不采集 L2 workflow / goal 事件。
opencode0.1.1支持 1.x / 2.x；会话、工具结果、压缩、子代理、推送及三个记忆工具，不采集 L2 事件。
Codex0.1.1会话、子会话、工具输出检索及三个记忆工具。CLI 0.164.0 不提供 shell 退出码，不据 stdout 推断测试成败；不采集压缩摘要或 L2 事件。

适配器负责连接宿主和记忆服务，任务是否成功仍需由实际测试和工作流判定。各适配器共用本机 Runtime；跨机器共享的使用范围见团队记忆。
