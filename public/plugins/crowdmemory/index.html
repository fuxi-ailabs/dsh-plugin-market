Crowd Memory

把一个 Agent 解决问题的经验，交给遇到同类问题的其他 Agent。

这是 DSH 的群体记忆插件。Agent 修好问题后留下记录；后续 Agent 在相关任务或失败出现时收到修法、出处和命中理由，再根据当前任务核对、使用。

DSH 插件 · 0.1.0
dsh plugin --profile web add @fuxi-ailabs/crowdmemory-dsh-adapter@0.1.0

先启动本机记忆服务；web 换成实际使用的 DSH profile。完整步骤见安装与验证。

使用场景

反复处理同类构建、配置或测试问题。前一个 Agent 已经查明原因，后来的 Agent 可以先看已有修法和出处，减少重复排查；项目路径或环境不同时，仍需调整并重新验证。

由多个 Agent 接力的 workflow。某个阶段留下的经验，可供后续运行或其他阶段的 Agent 参考。需要按阶段采集时，选用 workflow-default 模板，见工作流记忆。

团队里的 Agent 处理相近任务。跨机器共享还在内部预览，见团队记忆。当前可以先在本机验证经验如何在不同 Agent 之间流动。

操作录像

两个独立 Agent 处理同一份 zlib 小程序。Agent A 修好链接错误并记录实际做法；Agent B 在新的工作区取得这条记录，再运行构建检查。这里演示本机共享，不是跨机器团队发布。

使用前后

公开的 120 对受控合成任务中，固定模型和预算下，关记忆完成 45/120，开记忆完成 104/120。真实业务效果尚未验证；条件、原始数据及提炼流程的独立对照见评测。

安装与验证

需要 macOS 或 Linux、Node.js ≥ 22.18、Python ≥ 3.10（含 venv），以及支持范围内的 DSH（包括市场基准 0.2.1-rc.2）。本次录像使用 0.1.6-alpha.2，完整支持列表见组件与版本。下面将 Runtime 安装在独立项目目录，不使用全局 npm 安装。

1. 检查环境

终端
node --version
python3 --version
dsh --version

2. 在独立目录安装记忆服务

Runtime 会校验包内组件，并在指定目录建立独立 Python 环境。

终端 A
mkdir -p CMLocal && cd CMLocal
npm install --save-exact @fuxi-ailabs/crowdmemory-runtime@0.1.0
npx --no-install crowdmemory-runtime install --prefix "$PWD/.runtime/crowdmemory"

3. 启动记忆服务

保持这个终端运行；按 Ctrl-C 会停止服务。

终端 A · CMLocal 目录
npx --no-install crowdmemory-runtime start --prefix "$PWD/.runtime/crowdmemory"

4. 安装插件，让 DSH 连接这份 Runtime

另开终端并进入同一个 CMLocal 目录。web 可换成自己的 DSH profile；这个环境变量需要传给启动 DSH 的进程。

终端 B · CMLocal 目录
export CROWDMEMORY_ENDPOINT_FILE="$PWD/.runtime/crowdmemory/state/endpoint.json"
dsh plugin --profile web add @fuxi-ailabs/crowdmemory-dsh-adapter@0.1.0
dsh --profile web

5. 检查状态并尝试复用

另开终端，在 CMLocal 目录检查状态。然后让一个 Agent 修好问题并调用 memory_note；再开独立会话，让另一个 Agent 用 memory_search、memory_read 核对已有记录。

终端 C · CMLocal 目录
npx --no-install crowdmemory-runtime status --prefix "$PWD/.runtime/crowdmemory"
检查结果
  • Node.js ≥ 22.18，Python ≥ 3.10，DSH 版本在支持范围内。
  • 安装输出包含独立 Runtime 目录、Python 环境和 host-config.json。
  • 状态显示“Runtime 运行中”，端点位于安装目录的 state/endpoint.json。
  • DSH 中可以调用三个记忆工具；空库返回没有记录，已有记录带有出处。
  • 第二个 Agent 能读取第一个 Agent 留下的记录，并以实际测试验证修法。

常见问题

群体记忆只是跨会话保存聊天吗？

保存聊天只是保留原文。这里复用的是 Agent 留下的问题现象、原因和做法，记录附带出处与命中理由，并能统计是否被读取、采用，以及原失败步骤后来是否通过。本机共享和 workflow 已可用，跨机器团队共享仍为内部预览。

Runtime 已有 session-default，为什么还要选择 DSH profile？

两者不是同一个配置。DSH profile 决定把插件装在哪个 DSH 环境里，例如 web 或 desktop；Runtime 的 session-default / workflow-default 是记忆采集模板。详见配置。

Node.js 18 能用吗？必须全局安装吗？

发布包需要 Node.js ≥ 22.18。可以在独立目录用版本管理器选择合适的 Node，再按上面的本地 npm 安装步骤操作；不需要全局安装 Runtime。

为什么新的 Agent 没有收到刚写的记录？

笔记从下一个会话开始可见，同一会话不会推给自己。检查记录的 project/global 范围、两边是否连接同一份 Runtime，以及端点文件是否正确。桌面版从 Dock 启动时不会自动继承终端环境变量，配置方法见配置。

收到记忆就一定能修好吗？服务不可用怎么办？

不能保证。记录可能不适用或已经过时，Agent 仍需核对并运行测试。记忆服务离线或超时时，会话继续执行；这一步不带记忆，工具返回“记忆暂不可用”。更多排查见错误码和完整 FAQ。
