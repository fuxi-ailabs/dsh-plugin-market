使用场景与适合人群

适合使用 coding Agent 的应用开发者

修复代码与接口问题

“其他 Agent 是否修过类似的代码问题？”

让 Agent 查阅已有的问题定位和修法，核对当前代码、依赖版本与接口行为，再补修改和回归测试。

适合开发 workflow 的集成与维护者

在开发 workflow 中传递经验

“上一次在构建或测试阶段遇到过什么问题？”

把构建、测试阶段留下的排查经验提供给同机后续运行的 Agent。需要按开发阶段采集时，使用 workflow-default。

适合维护构建与测试环境的开发者

复用构建排错方法

“相同的构建失败以前是怎么修好的？”

记录编译、依赖或配置问题的原因、实际命令和检查结果。后续 coding Agent 可核对记录，在当前项目重新验证修法。

两个 Agent，复用一条启动脚本经验

Agent 1 处理 apriltag-python 的启动脚本问题，组织中心结合 Pillow、TA-Lib 的记录形成 trial 卡片，Agent 2 在 RDKit 任务中采用并复测。

  • Agent 1 复现子进程未获得原生库目录的问题，修复启动脚本并运行测试，记录原因、修法和验证结果。
  • 中心聚合独立项目的来源，核对本机证据、修改约束与一致性，将卡片发布到组织 trial。
  • Agent 2 收到组织卡片，调用 memory_read，按当前 RDKit 的 .libs 目录调整启动脚本，复测后通过 memory_note 引用该卡片。

案例在本机两个独立 Runtime 中运行，验证范围为启动脚本的子进程环境传递。截图与视频对应同一份开发版 trial 任务记录，结果概述见视频运行说明。

⌘ 在 DSH 中复现＋
发送给 DSH
在 macOS 或 Linux 中，使用已接入 Crowd Memory 的 DSH 重建视频的本机启动脚本任务。

先确认两个 Runtime 使用独立端点和数据库，连接同一组织中心的 Raw、Release 和共享组，并启用本机取证。中心已载入 apriltag-python、Pillow、TA-Lib 的独立来源记录，按证据核验结果处理 trial 发布。来源为 https://gitcode.com/third-party-library-for-harmony/migbot-experience-raw，仅按需浅取所需记录。

准备两个独立工作区。Agent 1 的 context.json 使用原生库目录 venv/lib/python3.12/site-packages/apriltag。Agent 2 使用 venv/lib/python3.12/site-packages/rdkit/.libs。任务核验父子进程的环境传递。两边使用下面的初始 launch-verification.sh。
#!/usr/bin/env bash
set -euo pipefail
native_dir=$1
shift
exec "$@"

为每边准备 test-launch.py，使用 unittest 覆盖以下检查。
1. 未继承路径时，子进程获得当前原生库目录。
2. 继承已有路径时，结果为当前目录加原有路径。
3. 搜索路径中没有空分量。测试通过启动脚本执行新的 Python 子进程读取 LD_LIBRARY_PATH。每次测试命令固定为 python3 test-launch.py。保存测试后，修复前后使用同一份测试文件。

Agent 1 先运行测试记录失败，修复 launch-verification.sh，再运行同一命令复测。用 memory_note 记录原因、实际 diff、环境条件和测试结果，scope=global，topic_key=harmony/native-loader-launch。

中心完成核验并发布 trial 后，确认节点 B 已同步卡片，再启动 Agent 2。Agent 2 先核对收到的组织卡片，用 memory_read 读取完整内容与出处，在自己的工作区复现失败，采用卡片中的做法并使用当前 RDKit 目录，只修改启动脚本，按原测试命令复测。最后用 memory_note 引用采用的组织卡片，展示推送、读取和引用记录。保留每次测试的退出码与输出。

安装与验证

以下为 macOS/Linux 的 Bash 命令。Windows PowerShell 安装步骤见 Agent 接入文档。

使用条件
运行平台
macOS、Linux 或 Windows 10/11；Python 需包含 venv。Windows 使用本用户回环 TCP 与前台 Runtime。
宿主与插件
adapter/runtime 0.2.0；DSH 支持 0.1.6-alpha.2 或 ^0.2.0-rc.2，包含市场基准 0.2.1-rc.2。
独立安装
Runtime 本地 npm 安装，在指定目录建立独立 Python 环境；不需要全局安装 Runtime。
适用范围和限制 ＋
开发任务范围

面向 coding Agent 的代码修复、构建排错、接口测试和开发 workflow，支持本机 Agent 共享经验与 workflow 阶段间传递记录。跨机器开发协作为内部预览；跨项目复用按 project/global 范围配置。

在当前项目重新验证

代码、依赖和运行环境变化后，原来的修法可能不再适用。Agent 采用前应核对条件，采用后运行当前项目的测试。记忆服务不可用时，开发会话继续执行，但这一步不带记忆。

配置与验证

DSH Profile 决定插件装在哪个环境，Runtime 的 session-default/workflow-default 是采集模板。实际连接取决于启动 DSH 的进程收到的端点配置。

  1. 1

    检查环境 确认 Node.js、Python 和 DSH 满足上面的条件。 终端

    node --version
python3 --version
dsh --version
  2. 2

    本地安装 Runtime 在独立目录安装 npm 包，Runtime 在 prefix 下建立隔离环境。 终端 A

    mkdir -p CMLocal && cd CMLocal
npm install --save-exact @fuxi-ailabs/crowdmemory-runtime@0.2.0
npx --no-install crowdmemory-runtime install --prefix "$PWD/.runtime/crowdmemory"
  3. 3

    启动记忆服务 保持前台终端运行；Ctrl-C 会停止服务。 终端 A · CMLocal

    npx --no-install crowdmemory-runtime start --prefix "$PWD/.runtime/crowdmemory"
  4. 4

    安装并连接 DSH 另开终端进入同一 CMLocal 目录，将端点传给 DSH。web 换成自己的 Profile。 终端 B · CMLocal

    export CROWDMEMORY_ENDPOINT_FILE="$PWD/.runtime/crowdmemory/state/endpoint.json"
dsh plugin --profile web add @fuxi-ailabs/crowdmemory-dsh-adapter@0.2.0
dsh --profile web
  5. 5

    检查状态并准备示例环境 另开终端检查本机 Runtime 状态。复现组织共享案例时，先按团队记忆文档准备中心与独立节点，再复制上面的示例任务。 终端 C · CMLocal

    npx --no-install crowdmemory-runtime status --prefix "$PWD/.runtime/crowdmemory"
检查结果 ＋
  1. 检查环境

    Node.js ≥ 22.18，Python ≥ 3.10，DSH 位于支持范围。

  2. 本地安装 Runtime

    安装输出包含 Runtime 目录、Python 环境及 host-config.json。

  3. 启动记忆服务

    Runtime 启动，并生成 state/endpoint.json。

  4. 安装并连接 DSH

    插件出现在该 Profile 中，Agent 可调用 memory_note、memory_search、memory_read。

  5. 检查状态并准备示例环境

    状态显示 Runtime 运行中。组织共享案例还需要中心、独立节点和满足核验条件的来源记录。

常见问题

哪些开发任务适合使用 Crowd Memory？＋

代码缺陷定位、接口修复、构建排错、回归测试和开发 workflow 中都会积累可复用的经验。Crowd Memory 将问题现象、原因、修法和验证结果提供给处理相关任务的 coding Agent。

开发经验如何形成并交给其他 Agent？＋

Runtime 记录任务轨迹和经验笔记，保留问题、实际修改、适用条件与验证结果。在后续任务启动、相关失败出现或进入 workflow 阶段时，适配器向 Agent 提供匹配的记忆卡、来源和命中理由。Agent 也可以主动读取记录。

多个 Agent 可以怎样共享经验？＋

本机多个 Agent 可以通过 Runtime 共享记录，并按项目或全局范围使用。跨机器协作通过组织中心交换经验，当前处于内部预览；视频展示开发版的 trial 组织试推流程。

如何判断已有经验适用于当前任务？＋

Agent 可以核对记录中的失败现象、代码位置、依赖版本、运行环境和验证结果，结合当前任务调整修改，并运行当前工程的回归测试。

如何接入正在使用的 coding Agent？＋

通过 Adapter 将 coding Agent 连接到本机 Runtime。本页“安装与验证”提供 DSH 的独立安装与验证步骤；OpenClaude、opencode 和 Codex 的接入方式见页脚的 Agent 接入文档。
