DoG · DAG of Goals 价值判断器 v2.0.0-alpha.1

经院哲学式展开，落到原子目标。标准由你确认，判定隔离执行。

DoG 是一个把非形式化目标拆成 DAG、交给隔离上下文的 Agent 逐条判定的价值判断器。「文章好不好」这种目标没有形式化标准，并且具体意图也取决于具体某个人的偏好。DoG 把这类目标拆成一张有向无环图（DAG）：根节点是用户的原始目标，按「经院哲学」式的风格进行详尽的内涵展开，保证完备性、不遗漏、抽象层合理，在展开的过程中帮助用户明确自己的目标，发现内涵中新的外延。最终下层拆成原子目标，由 Agent 判断。你把你的（或者 Agent 的）产物给了 DoG ，一系列 Agents 在隔离上下文判断产物是否达标，最终总的价值判断的质量相比只喂给 Agent 「这篇文章好不好」会大幅提高。产物可以是文章、PPT、代码仓、项目，或者一天的生活。我们做高质量的判定器。

终端
dsh plugin --profile web add @fuxi-ailabs/dsh-dog@2.0.0-alpha.1

把 web 换成你实际在用的 profile 名；默认不需要配置：被检查的文件按当前会话的目录找，判定沿用当前会话的模型。 安装步骤 ↓

使用场景与适合人群

适合写文档或文章的人

文章「像 AI 写的」，但说不出改哪句

「读着别扭，可我说不出是哪里。」

把「AI 味」拆成能单独查的子目标：套话、句式单调、模糊用语、同一个所指在一篇文章中非得有多个能指、非得用比喻式的动词、标题喜欢带动词之类的。每条由独立判定者给证据，你按证据改。

适合用 skill 或子 agent 产出东西的人

产物交上来了，但没按 skill 的要求

「它说遵守了 skill，哪一条哪里遵守了？」

把 skill 里每条要求写成判据，逐条判定并留证据；判定会话在独立上下文，看不到生成会话的自我描述。

适合想给「项目」或「一天」做评价的人

想评价的东西没有固定格式

「这周过得怎么样，能不能有个说得清的评价？」

只要评价对象能落成文件（日志、清单、报告、截图），就能建图判定。

从一句话到一张图

前两步是人机来回，后两步是命令。插件自带一个写图用的 skill（dog-v02-agentic-ci），装好后 Agent 就知道怎么和你一起写图：先立抽象层、每一层请你确认、写完用元图自检。

  • 说目标：把你自己的原话交给 Agent，比如「这篇文章我读着别扭，可说不出哪句不对」。
  • 拆图：Agent 按经院哲学式展开，先把抽象层摆正，再逐层落到原子目标。每一层都请你确认；你说不清的地方，它继续问，问到能写成判据为止。
  • 自检：图写完先跑一遍元图（用一张检查图结构的图去判这张图），看抽象层有没有混杂、目标有没有重叠、判据是否可判。
  • 运行：dog_create 把产物和背景文档固化成一个不可改的副本，dog_run 按 DAG 顺序开判定，每个判定最多跑 900 秒。
  • 看结果：dog_status 列出每个目标的判决与证据；在调试面板里选中一个目标，右边那一栏就是它的判定、证据与事件。

同一个目标，两种做法

同一篇 1,613 字节的文章，左边是直接问模型「这篇文章好不好」，右边是拆成图后逐条判定。

之前：直接问一句

模型给出「好文章，合格偏上」和一组分数，依据是它自己的阅读印象；没有判据，没有逐条证据，也没有记录为什么是这个结论。

之后：拆成图，逐条判定

八个目标各自判定，六个通过、两个失败；失败的那个整体断言说明了「四个子目标都过、整体仍然不成立」，每个结论都能点开看证据。

↳ 「完成」变成一个可核对的说法。

↳ 判不出来的时候，系统停下来找你。

↳ 判据、产物、判定记录都在，能查到当时凭什么这么判。

常见问题

它和 CI 有什么区别？＋

能被脚本判定的部分交给普通 CI。DoG 处理的是不能程序化的那部分：很多目标能用一句话说清楚，却不容易写成一个程序，这类才需要 DoG。一条分支也不能全靠脚本判完。

判据谁写？＋

你和 Agent 一起写。写图时它会请你确认：写图前、拆解后、运行前各一次。根节点是你的原话，Agent 的解读不算数。

判定准不准？＋

单次判定是信号。同一张图多跑几次，稳定出现的失败才值得动手；偶尔翻转的结果先放着。

一个判定要多久？＋

默认上限 900 秒，可以在配置里改（runDeadlineSeconds）。超过上限按「目标不够原子」记为需要人工，不重试；把目标拆小更划算。

判定者会改动我的产物吗？＋

判定读的是 dog_create 时固化的副本；工作区后续改动不会进入这次判定。生成产物的活由你或你的 Agent 做。

要花多少钱？＋

每条判据一次独立会话。运行预算用 runMaxTokens 控制，0 表示不设限；预算耗尽时，跑到一半的判定会被中止，运行按「未完成」结束并说明原因。

产物改了要重新确认吗？＋

不用。要重新确认的是判据：图的结构、每个目标写的那句话、脚本内容、背景文档，这几样里任何一样改了都要重新确认；只换了被检查的产物，不用。

判定者和生成者用同一个模型，算自己判自己吗？＋

算同一族。运行条件会标出这一点。要换成另一个模型族，配 crossCheckProvider / crossCheckModel，确认时把要交叉的目标一起定下来。
